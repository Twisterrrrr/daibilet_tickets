# Staging: секреты и почему нет данных

## Обязательные переменные (без них бэкенд не стартует или падает)

| Переменная | Назначение |
|------------|------------|
| `POSTGRES_PASSWORD` | Пароль БД. В docker-compose помечена как обязательная (`?`). |
| `ADMIN_INITIAL_PASSWORD` | Пароль первого админа. В compose обязательная. |
| `JWT_SECRET` | Секрет для JWT (auth, user, supplier). В коде: `config.getOrThrow('JWT_SECRET')` — при старте без неё приложение падает. |

Остальное (REDIS_PASSWORD, CORS_ORIGIN, APP_URL и т.д.) имеет дефолты в compose или в коде.

---

## Переменные для появления данных на сайте

### 1. Каталог/события (Ticketscloud)

Данные о событиях и площадках подтягиваются **синхронизацией** с Ticketscloud, а не из seed.

| Переменная | Назначение |
|------------|------------|
| `TC_API_TOKEN` | Токен API Ticketscloud. Без него: «TC_API_TOKEN не установлен — синхронизация невозможна» / gRPC не инициализируется. |
| `TC_WIDGET_TOKEN` | Токен виджета (виджет покупки на фронте). |
| `TC_GRPC_ENDPOINT` | По умолчанию `simple.stage.freetc.net:443` для staging. |

Если `TC_API_TOKEN` пустой — синхронизация не запускается, каталог и события будут пустыми. После заполнения нужно один раз запустить полную синхронизацию (админка или job `sync-incremental` / скрипт full-sync).

### 2. Регионы, города, админ, тестовые пользователи (seed)

Эти данные создаются **сидами** в БД.

- **Миграции:** без применённых миграций сиды падают (например, ошибка колонки `trustScore`).
- **Секреты для сидов:** те же `POSTGRES_*`, в контейнере seed передаётся `DATABASE_URL`, `ADMIN_INITIAL_EMAIL`, `ADMIN_INITIAL_PASSWORD`.

Порядок:

1. Применить миграции:  
   `docker exec daibilet-staging-backend npx prisma migrate deploy`
2. Запустить сиды (см. `deploy/staging/run-all-seeds.sh` или блок seed в `deploy.sh`).

## Проверка «все ли секреты заполнены» на сервере

Без вывода самих значений (только факт «задан / не задан»):

```bash
cd /opt/daibilet
for v in POSTGRES_PASSWORD ADMIN_INITIAL_PASSWORD JWT_SECRET TC_API_TOKEN TC_WIDGET_TOKEN REDIS_PASSWORD; do
  if grep -q "^${v}=.\+" .env 2>/dev/null; then echo "$v: задан"; else echo "$v: НЕ ЗАДАН"; fi
done
```

## Кратко: почему на staging нет данных

1. **Бэкенд не работал** (например, падал из‑за `dotenv` или `JWT_SECRET`) — запросы к API не доходят, фронт показывает пусто.
2. **Не применены миграции** — сиды падают, БД без регионов/городов/админа.
3. **Не запущены сиды** — нет регионов, городов, тестовых пользователей, админа.
4. **Не задан TC_API_TOKEN** — синхронизация с Ticketscloud не идёт, каталог/события пустые.
5. **Синхронизация не запускалась** — даже при заданном `TC_API_TOKEN` данные появятся только после хотя бы одного успешного запуска sync (full-sync или job в админке).

Рекомендуемый порядок после деплоя: миграции → сиды → проверить `TC_*` → один раз запустить полную синхронизацию.
