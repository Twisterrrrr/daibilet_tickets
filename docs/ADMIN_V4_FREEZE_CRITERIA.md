# Admin V4 — Freeze Criteria (Imported Sales)

Этот документ фиксирует **текущий замороженный scope Admin V4** для контура Imported Sales и определяет критерии выхода в следующие фазы.

Принцип: в фризе мы **не расширяем продукт**, а доводим качество, стабильность, предсказуемость и операционную готовность.

---

## 1) Current scope frozen (что входит)

Функционально Admin V4 в текущей фазе — это **read-only control plane** поверх существующих backend admin endpoints (без изменения контрактов).

Замороженные модули/разделы:

- **Dashboard**
- **Events**
- **Venues**
- **Cities**
- **Landings**
- **Collections**
- **Import Sources**
- **External Orders**
- **Taxonomy**
- **SEO**
- **Linking**
- **Redirects**
- **Audit**
- **Settings**

Инварианты фриза:

- UI **не добавляет** write‑операции и не меняет бизнес‑процессы.
- URL‑state фильтров сохраняется.
- Ошибки и пустые состояния различаются (no silent failures).
- Производительность list‑страниц приемлема (без запроса на каждый символ).

---

## 2) Intentionally out of scope (что НЕ делаем до следующих фаз)

До отдельного утверждения и следующей фазы **вне scope**:

- **Supplier LC** (поставщик как продукт/маркетплейс‑сущность, lifecycle, self-service)
- **finance / EDO / reconciliation** (сверки, акты, ЭДО, бухгалтерия)
- **internal checkout / internal orders** (внутренний чекаут и собственные заказы)
- **RBAC full matrix** (полная матрица ролей/разрешений и UI‑политики)
- **Promo Blocks**
- **Articles / blogger columns**
- **B2B API layer**
- **Trip Planner**

Важно: отсутствие в scope означает «не обещаем и не строим сейчас», даже если endpoints существуют.

---

## 3) Criteria for Phase B — Supplier Marketplace

Фаза Supplier Marketplace может стартовать, когда выполнены критерии:

- **Data correctness**: стабильный импорт, предсказуемые события/сессии/офферы, нет систематических stale источников.
- **Operational readiness**: есть runbook, мониторинг/процедуры, ясная эскалация, известные failure‑кейсы.
- **Contract readiness**: определён минимальный backend контракт Supplier Marketplace (модели/DTO/эндпойнты) без «ломающих» миграций.
- **Security**: согласованы роли/ограничения доступа для поставщиков (не через скрытие меню).
- **UX**: утверждён MVP пользовательский поток поставщика (регистрация/доступ/каталог/статусы), без расползания в «CRM».

---

## 4) Criteria for Commerce / Internal Orders

Переход к внутренним заказам/коммерции возможен, когда:

- есть **единая модель заказа** (статусы, оплаты, возвраты, idempotency)
- определены источники истины (provider vs наша система)
- есть безопасная обработка PII/финансовых данных (минимизация доступа)
- есть согласованный контур саппорта и аудит/журналирование критичных действий

---

## 5) Criteria for Media / Articles

Старт медийного слоя возможен, когда:

- определён контент‑пайплайн (создание/публикация/ревью)
- есть правила перелинковки с каталогом и SEO‑инварианты
- есть метрики качества (SEO audit / coverage / canonical) и ответственность редакции

---

## 6) Criteria for Promo / Marketing layer

Промо‑слой (Promo Blocks и т.п.) стартует, когда:

- определены точки встраивания (где/как показываем)
- есть гарантия, что промо не ломает SEO/каноникал/навигацию
- определены ограничения для безопасного редактирования (validation, preview, rollout)
