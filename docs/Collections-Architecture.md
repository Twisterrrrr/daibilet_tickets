# Collections Architecture

## Formula

Collection = `city + eligibility filters + ranking rules + manual overrides`.

- `cityId` is a first-class field (no city-only JSON).
- `filters` and `ranking` are stored as JSON configs, edited in form-based admin UI.
- `pinnedEventIds` and `excludedEventIds` are explicit override channels.

## Data Model

`Collection` includes:

- identity: `id`, `cityId`, `slug`, `title`, `subtitle`
- selection config: `filterTags`, `filterCategory`, `filterSubcategory`, `filterAudience`, `additionalFilters`, `rankingJson`
- workflow: `sourceType`, `selectionBasis`, `status`, `semanticKey`
- preview/cache: `eventCountCached`, `previewGeneratedAt`
- overrides: `pinnedEventIds`, `excludedEventIds`

Statuses:

- `DRAFT` -> editable draft
- `SUGGESTED` -> generated by engine, pending admin decision
- `ACTIVE` -> public
- `REJECTED` -> rejected suggestion
- `ARCHIVED` -> historical

## Selection Layer

Shared service: `CollectionSelectionService`.

Pipeline:

1. City filter (`cityId` or `citySlug`)
2. Eligibility filters (tags/category/subcategory/audience/additional)
3. Ranking preset (`popularity`, `availability`, `balanced`)
4. Overrides (`pinned` first, `excluded` removed)

This service is reused by:

- collection page responses
- suggestions generation preview/count
- landing selection (city landing routes)

## Suggestions Engine

Service: `CollectionSuggestionService`.

MVP rules:

- only published/eligible events
- grouped per city
- limited candidate set:
  - popular-driven
  - structural-driven
  - limited combinations

Thresholds:

- `MIN_EVENTS_FOR_SUGGESTION`
- allowed sets in `collection-suggestion.config.ts`

Dedup:

- `semanticKey = cityId + normalized filters`
- if existing `SUGGESTED` found -> update preview/count
- if existing `MANUAL/ACTIVE` for same semantic key -> skip creation

## Admin Workflow

`/admin/collections` supports:

- filters: `status`, `sourceType`, `selectionBasis`, `city`, `search`
- actions for suggested rows:
  - `POST /admin/collections/:id/approve` -> `ACTIVE`
  - `POST /admin/collections/:id/reject` -> `REJECTED`
- generation:
  - `POST /admin/collections/suggestions/generate`

## Public API

- new: `GET /catalog/collections?city=...`
- new: `GET /catalog/collections/:citySlug/:slug`
- bridge (kept): `/collections*`
