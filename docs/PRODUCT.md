# Product — поведение продукта для пользователя и бизнеса

**Назначение:** миссия, конкурентная рамка, ключевые пользовательские контуры (каталог, лендинги, заказ), продуктовые правила (что продаём / что откладываем). Технические инварианты — в [`SYSTEM.md`](SYSTEM.md).

**Связь:** [`PROJECT-FOUNDATION.md`](PROJECT-FOUNDATION.md), [`product/landings.md`](product/landings.md), [`product/finance.md`](product/finance.md), [`core/events.md`](core/events.md).

---

## 1) Миссия

Агрегатор билетов на экскурсии, музеи и мероприятия с умным подбором программы поездки. Стартовые города: Москва, Санкт-Петербург, Казань, Калининград, Владимир, Ярославль.

---

## 2) Конкурентная стратегия (кратко)

Ориентир рынка — Tripster. Не конкурируем «в лоб» по общему UX; усиливаем:

1. **Многоуровневая таксономия и SEO-поверхность** (города, подкатегории, теги, лендинги).
2. **AI-контент** с привязкой к реальным данным (цены, наличие, расписание) + редактура.
3. **Планировщик туров** как долгосрочный дифференциатор.

---

## 3) Ключевые пользовательские контуры

- **Каталог и карточки** событий/площадок — публичный frontend; канон URL и лендинги — [`product/landings.md`](product/landings.md).
- **Покупка / checkout / виджеты** — инварианты [`core/checkout.md`](core/checkout.md).
- **Личный кабинет покупателя** — обзор в бэкапе `Project.md.full-backup` § Buyer Account; детали по мере актуальности.
- **Preview** черновиков событий/площадок — HMAC-токены, `noindex`; см. бэкап § Preview.

---

## 4) Admin V2 / V3 (продуктовая роль)

- **V3** — основной операционный UI (`/admin-v3/*`): каталог, качество, контент, support, ops. Не цель — перенос всего V1.
- **V1** — toolbox для редких сценариев.
- **V2** (если упоминается в трекере) — отдельный слой/долг; стратегия в [`Tasktracker.md`](Tasktracker.md), не смешивать с каноном V3 без явной задачи.

Подробнее по фазам V3: [`admin-v3/grand-master-plan.md`](admin-v3/grand-master-plan.md), кратко: [`ADMIN_V3.md`](ADMIN_V3.md).
