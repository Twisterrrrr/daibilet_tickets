# Admin Health Dashboard — задел (Phase 5+)

**Цель:** использовать витрину `SupplierDailyStat` в админке для выявления «падающих» поставщиков (резкое снижение выручки или конверсии).

## Источник данных

- Та же витрина `supplier_daily_stats`: агрегаты по дням на оператора.
- Дополнительно можно опираться на `Operator` (successfulSales, trustLevel) и при необходимости на сырые `PaymentIntent` для детализации.

## Идеи метрик

1. **Спад выручки (WoW):** сравнить сумму `supplierAmountCents` за последние 7 дней с суммой за предыдущие 7 дней. Если падение выше порога (например −30%) — в список «требует внимания».
2. **Нулевая активность:** поставщики, у которых за последние N дней нет ни одной строки в витрине при наличии активных событий/офферов.
3. **Конверсия (когда появятся viewsCount):** резкое падение conversionRate по сравнению с предыдущим периодом.

## Эндпоинт (задел)

- **GET /admin/analytics/supplier-health** (или /admin/suppliers/health):
  - Параметры: `windowDays=7`, `minDropPercent=30`.
  - Логика: по каждому оператору с хотя бы одной записью в витрине за последние 14 дней посчитать сумму за дни [0..6] и [7..13]; если (prev - curr) / prev >= 0.3 — вернуть в списке с полями operatorId, name, currentWeekRevenue, previousWeekRevenue, dropPercent.
  - Ограничение: только операторы с isSupplier = true (или по наличию событий).

## Реализация

- Сервис в `packages/backend/src/admin` или общий `SupplierDailyStatService.getSupplierHealthRanking(windowDays, minDropPercent)`.
- Контроллер админки вызывает сервис и отдаёт JSON для таблицы/дашборда во фронте админки.

После внедрения витрины и трендов в ЛК поставщика этот слой закрывает Phase 5 и даёт основу для мониторинга мерчантов в админке.
