## Популярные направления — Blueprint

> Цель: сделать лендинги и подборки по темам (ночные мосты, салюты, автобусные туры и т.п.) самодостаточными: они автоматически включаются / выключаются на основе реального наличия живых событий с будущими сеансами.

### 1. CollectionMaterializerService (авто-управление подборками)

- **Проблема сейчас**: коллекции из `seed-collections.ts` по сути всегда `isActive = true`. Если по фильтрам нет ни одного события с будущей сессией, подборка всё равно висит в `/podborki` и блоках «Популярное», давая пустой экран.
- **Решение**: ввести для `Collection` параметр порога `minEvents` и сервис-материализатор, который пересчитывает флаг `isActive` по факту.

**Изменения в модели (`schema.prisma`):**

- Расширить `model Collection`:
  - `minEvents Int @default(1)` — минимальное количество подходящих событий (с future-сессиями), при котором подборка считается живой.
  - Уже существующие поля `isActive`, `isDeleted` переиспользуем, семантика прежняя.

**Сервис `CollectionMaterializerService`:**

- Новый класс в `src/collection/collection-materializer.service.ts`:
  - Метод `recomputeAll(now: Date = new Date())`:
    - читает все не удалённые коллекции (`isDeleted = false`),
    - для каждой строит `Prisma.EventWhereInput` по тем же правилам, что `CollectionService.buildEventFilter`:
      - фильтр по городу (`cityId` или `citySlug`),
      - `filterTags` (OR по тегам),
      - `filterCategory`, `filterSubcategory`, `filterAudience`,
      - обязательный признак живого расписания:
        - `sessions.some({ isActive: true, startsAt: { gt: now } })`.
    - считает `eventsCount` (через `event.count`),
    - выставляет `isActive = eventsCount >= minEvents`.
  - Логгирует для каждой коллекции: `slug`, `eventsCount`, `minEvents`, итоговый `isActive`.

**Интеграция:**

- Подключить сервис в `CollectionModule` и зарегать в `AppModule`.
- Добавить cron-задачу (например, в `SyncProcessor` или отдельном `SchedulerService`):
  - `@Cron('0 */1 * * *')` → `collectionMaterializer.recomputeAll()`.
- Добавить админ-операцию:
  - `POST /admin/collections/materialize` → ручной вызов `recomputeAll()` с JSON-ответом (список коллекций и их актуальный `eventsCount`).

**Поведение:**

- Подборка:
  - **видна** в `/podborki` и связанной витрине, только если `eventsCount >= minEvents`;
  - **автоматически скрывается**, если после синка / retag’а / изменения расписания future-сессий становится меньше порога.

### 2. Расширение auto-tagging (canonical-tag-enrichment)

- **Проблема сейчас**: часть тематик (автобусы, метеоры, крыши, пешеходные туры) требуют ручной разметки или точечных сидов.
- **Решение**: аккуратно расширить словарь `KEYWORD_TAG_MAP` и использовать его как источник правды для новых лендингов/подборок.

**Новые теги / темы:**

- `bus-tour` — обзорные автобусные экскурсии / Hop-On Hop-Off:
  - триггеры в title/description: `автобус`, `автобусн`, `двухэтажн`, `двухэтажном`, `hop on`, `hop-off`, `hop on - hop off`.
- `meteor` — прогулки на метеорах:
  - триггеры: `метеор`, `комета` + контекст воды (`Нева`, `залив`, `ракета` при наличии водной лексики).
- `rooftop` — экскурсии по крышам:
  - триггеры: `крыша`, `по крышам`, `крышам`, `rooftop`.
- `walking` — пешеходные экскурсии:
  - триггеры: `пешеходн`, `пешая`, `пешком`, `walking tour`.

**Технически:**

- Расширить `KEYWORD_TAG_MAP` в `canonical-tag-enrichment.ts`:
  - ключ → массив `tags: string[]`;
  - триггеры должны быть максимально специфичными, по возможности фразами, а не отдельными словами (чтобы уменьшить шум).
- Убедиться, что:
  - `TcSyncService` и `TepSyncService` вызывают enrichment при создании/обновлении события (retagAll уже использует canonical-tag-enrichment).
  - при необходимости добавить unit-тесты для новых кейсов (особенно для «автобус», `Hop-On Hop-Off` и «метеор»).

### 3. Новая подборка «Обзорные автобусные экскурсии»

- **Коллекция** `obzornye-avtobusnye-ekskursii` уже добавлена в `prisma/seed-collections.ts` (кросс-городская, `filterTags: ['bus-tour']`).
- Тег `bus-tour` создаётся/активируется в том же сиде.
- Для наполнения подборки:
  - автоматический путь — расширенный auto-tagging (`bus-tour` по ключевым словам);
  - точечная доразметка — SQL/Prisma-скрипт, который навешивает `bus-tour` на известные автобусные события из Teplohod/Ticketscloud.

### 4. Динамический «Топ направлений» по городу

- **Цель**: на странице города отображать не только жёстко заданный список лендингов/подборок, но и динамический ТОП тем, реально «живущих» сейчас.

**Backend:**

- Новый метод в сервисе каталога или отдельном `RegionService`:
  - `getTopTagsByCity(citySlug: string, limit = 5)`:
    - считает для каждого тега `eventsCount` в данном городе среди событий:
      - `isActive = true`, `isDeleted = false`,
      - есть future-сессии (`sessions.some(isActive=true, startsAt>now)`),
      - `eventsCount > 0`.
  - опционально: `getTopCollectionsByCity(citySlug?: string, limit = 5)`:
    - переиспользует логику материализатора для `Collection` и отдаёт самые «богатые» подборки.

**Frontend:**

- На странице города:
  - блок «Популярные направления» строить из:
    - активных лендингов (`LandingService.getByCitySlug`),
    - активных коллекций (`CollectionService.getCollections(citySlug)`),
    - дополнительно — из `getTopTagsByCity`, как fallback/расширение.
  - Ссылка по тегу: `/tags/{slug}?city={citySlug}`.
  - Ссылка по подборке: `/podborki/{slug}?city={citySlug}` (для кросс-городских).

### 5. Риски и контроль качества

- **Шум auto-tagging**:
  - не использовать слишком общие триггеры без контекста (например, одиночное «ночь» без связки с водой/городом);
  - вносить новые правила батчами, с обязательной проверкой на staging:
    - SQL-отчёт по новым тегам (сколько событий, в каких городах),
    - ручной просмотр нескольких карточек.
- **Пустые подборки/лендинги**:
  - обязательно опираться на `minEvents` и материализаторы:
    - лендинги уже закрываются через `LandingMaterializerService` и `TopicDefinition.minEvents`;
    - коллекции — через новый `CollectionMaterializerService`.
- **Инциденты после смены поставщика**:
  - при существенных изменениях в текстах на стороне провайдера (Teplohod/TC) пересматривать словарь триггеров и `minEvents` для тем, которые внезапно начали включаться/выключаться.
