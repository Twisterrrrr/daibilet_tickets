# Чат и поддержка — полная спецификация (состояние на 2026-04-14)

Документ описывает **весь контур поддержки**: онлайн-чат на витрине, тикеты (формы), админку (Admin V3), API, данные в БД, уведомления и известные пробелы. Тикеты и чат логически объединены в раздел **«Поддержка»** в админке; счётчик «inbox» агрегирует оба канала.

---

## 1. Термины

| Термин | Смысл |
|--------|--------|
| **Чат (live chat)** | Диалоги `ChatConversation` / `ChatMessage`, гость с сайта идентифицируется **guest token** (хранится только hash в БД). |
| **Тикет** | Обращение `SupportTicket` из формы помощи (`/help` и аналоги), со своим жизненным циклом и ответами `TicketResponse`. |
| **Inbox (бейдж)** | Агрегат: «чаты, где клиент написал после последнего ответа админа» + «открытые/активные тикеты» по правилам `getInboxCounts()`. |

---

## 2. Что уже сделано

### 2.1. База данных (Prisma)

- **`ChatConversation`**: статус (`ChatConversationStatus`), гость (`guestName`, `guestEmail`, `guestPhone`), опционально **`userId`** (для привязки к залогиненному пользователю — поле есть, сценарий не доведён до виджета), **`guestTokenHash`**, служебные **`lastCustomerMessageAt`** / **`lastAdminMessageAt`** для «нужен ответ».
- **`ChatMessage`**: автор (`ChatAuthorType`), текст, опционально `authorAdminId` для сообщений оператора.
- **`ChatTelegramOperatorState`**: заготовка под Telegram-оператора (активный диалог); **кода бота/интеграции в репозитории нет** — только схема.
- **`SupportTicket`** + **`TicketResponse`**: полный контур тикетов (категория, приоритет, SLA, статусы, внутренние/публичные ответы).

### 2.2. Backend API

**Публичный чат (без JWT пользователя)**

| Метод | Путь | Назначение |
|-------|------|------------|
| `POST` | `/api/v1/chat/start` | Создать диалог + первое сообщение; ответ: `conversationId`, `guestToken`. Throttle, honeypot. |
| `GET` | `/api/v1/chat/:id/messages?after=` | Сообщения гостя (Bearer = guest token). |
| `POST` | `/api/v1/chat/:id/messages` | Отправить сообщение от гостя. |

Реализация: `ChatController`, `ChatService` (`packages/backend/src/chat/`).

**Админ-чат**

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/api/v1/admin/chat/conversations` | Список; query: `status`, `needsReply`, `search`, `limit`. |
| `GET` | `/api/v1/admin/chat/conversations/:id/messages` | История. |
| `POST` | `/api/v1/admin/chat/conversations/:id/messages` | Ответ оператора. |

Реализация: `AdminChatController`, роли `ADMIN` / `EDITOR`, аудит.

**Тикеты (публичное создание и просмотр по коду)**

- Создание и чтение — через `SupportService` и публичные роуты поддержки (см. `support.controller` / модуль support — не дублировать здесь все пути).

**Админ: поддержка и inbox**

| Метод | Путь | Назначение |
|-------|------|------------|
| `GET` | `/api/v1/admin/support/tickets` | Список тикетов с пагинацией. |
| `GET` | `/api/v1/admin/support/tickets/:id` | Деталь. |
| `PATCH` | `/api/v1/admin/support/tickets/:id` | Статус / назначение. |
| `POST` | `/api/v1/admin/support/tickets/:id/reply` | Ответ; не-internal → письмо клиенту, статус `WAITING_CUSTOMER`. |
| `GET` | `/api/v1/admin/support/stats` | Сводка по тикетам (для дашборда и т.д.). |
| `GET` | `/api/v1/admin/support/inbox-count` | `{ chatNeedsReply, openTickets, total }` — для бейджа в UI. Роли включают `VIEWER`. |

Реализация: `AdminSupportController`, `SupportService.getInboxCounts()`:

- **Чаты «нужен ответ»**: среди `OPEN` диалогов — последнее сообщение клиента новее, чем последний ответ админа (или ответа не было).
- **Тикеты**: считаются статусы `OPEN`, `IN_PROGRESS`, `WAITING_CUSTOMER`.

### 2.3. Почта

- При новом сообщении клиента в чате вызывается **`MailService.notifyAdminChatNeedsReply`** (fire-and-forget).
- Новые тикеты — **`notifyAdminNewTicket`**; ответ клиенту по тикету — **`sendTicketReply`**.

### 2.4. Публичный фронт (`packages/frontend`)

- **`ChatWidget`** (`src/components/ui/ChatWidget.tsx`): плавающая кнопка, форма имени/email/первого сообщения, сохранение сессии в `localStorage` (`daibilet_chat_v1`), long-polling новых сообщений раз в **4 с**, оптимистичное отображение своих сообщений.
- Подключение виджета — в **`layout`** (глобально на сайте).

### 2.5. Admin V3 (`packages/frontend-admin-v3`)

- Навигация: секция **«Поддержка»** — пункты **Чат** и **Тикеты** (`src/config/navigation.ts`).
- **Бейдж** на пункте «Чат»: хук **`useAdminInboxCount`** → `GET /admin/support/inbox-count`, отображается сумма **`total`** (`Sidebar.tsx`).
- Страницы:
  - **`/admin-v3/chat`** — список диалогов с меткой «ждёт ответа».
  - **`/admin-v3/chat/:id`** — переписка, отправка ответа, refetch / инвалидация inbox.
  - **`/admin-v3/tickets`** — список тикетов API.
  - **`/admin-v3/tickets/:id`** — деталь тикета (если подключена страница).

## 3. Что нужно сделать (пробелы и улучшения)

Приоритеты ниже — рабочая классификация для бэклога; точные сроки — в `Tasktracker.md`.

### 3.1. Критичные / высокие

| # | Задача | Почему |
|---|--------|--------|
| 1 | **Закрытие диалога (`CLOSED`)** | В Prisma есть `ChatConversationStatus.CLOSED`, но **`ChatService` нигде не переводит диалог в `CLOSED`**; в `AdminChatController` нет `PATCH` для статуса. Список может фильтровать по `status`, но оператор не может формально закрыть тред из UI. |
| 2 | **Согласованность inbox** | Бейдж сейчас на «Чат»; продуктово может понадобиться один индикатор на всю секцию «Поддержка» или дублирование на «Тикеты», чтобы не создавать впечатление «только чат». |
| 3 | **Авторизованный пользователь = тот же чат с `userId`** | В схеме есть `userId`, виджет его не проставляет — восстановление истории в ЛК и защита от потери токена не реализованы. |

## 4. Что можно отложить

- **Полная замена polling на realtime** — пока нагрузка умеренная, можно жить с 4 с / 15 с.
- **Telegram** — до появления выделенного владельца и требований к каналу.
- **Глубокая склейка тикета и чата в один тред** — дорого; достаточно связки по email/коду заказа вручную.
- **ЛК поставщика для поддержки** — вне текущего scope (см. общий roadmap).

---

## 5. Безопасность (кратко)

- Guest token: только **hash** в БД; сравнение через `timingSafeEqual` по SHA-256.
- Неверный токен → **404** на сообщениях (не раскрывать существование id).
- Throttle на публичных эндпоинтах чата.
- Honeypot поле `honey` на старте и отправке сообщений.
