# Checkout — инварианты и контракты (каноническая сводка)

Этот документ фиксирует **инварианты checkout/виджет‑потока**, которые нельзя ломать при изменениях в админке, витрине и операционке.

Источник детальной истории: `docs/archive/PR-C0-C7-Final.md` (legacy, но полезно как референс).

---

## 1) Контуры и роли

- **Widgets Read API**: виджет читает событие + сеансы, доступность, теги и bestOption.
- **Checkout create**: создание checkout-сессии и редирект/оплата.
- **Payment webhook**: идемпотентная обработка, постановка задач, fulfilment.
- **Fulfilment**: выдача артефактов/билетов без дублей.

---

## 2) Ключевые инварианты

### 2.1 Идемпотентность

- Повторный вызов webhook не должен плодить дубликаты логов/операций и не должен повторно выдавать билеты.
- Повторное выполнение fulfilment не должно создавать дополнительные `FulfillmentItem`.

### 2.2 `bestOption`

- `bestOption=true` ровно у **одного** сеанса на событие.\n+- Критерий: **минимальный `startsAt` среди доступных** (available > 0).\n+- Если доступных сеансов нет — `bestOption` у всех false.

### 2.3 Доступность (effectiveAvailable)

- Availability учитывает **paid + holds**.\n+- Holds включают `AWAITING_PAYMENT` (чтобы окно оплаты не раздувало доступность).

---

## 3) Что важно для Admin V3 (операционный слой)

- Любые admin‑операции, влияющие на расписание/квоты/продажи, должны сохранять инварианты идемпотентности и доступности.\n+- Экспорты/аудит/ручные операции должны быть безопасны (см. guardrails в `docs/runbooks/infra.md`).
